# RoboCup 巡逻机器人上位机

这是我们为 RoboCup 中国赛巡逻机器人开发的 Python 上位机，运行在 RDK 上，通过串口和 STM32 底盘通信。

## 这份代码里有什么

- **巡逻与运动控制**：按地图规划和执行巡逻路线，处理路口转弯、道路居中、返航和停车。道路方向学习结合两侧激光、陀螺仪和轮程，为居中和回正提供参考。
- **竞赛任务**：支持 RFID 巡逻卡读取与语音播报、障碍物检测与避障，以及涵洞场景下的人脸和刀具识别。项目保留了各阶段的独立入口，方便单独调试。
- **部署与调试**：下方记录了运行入口、硬件配置和调试方法。连接实车前，请先阅读 [实车验收说明](VEHICLE_ACCEPTANCE.md)，部分测试入口会直接控制电机或舵机。

## car_app 运行说明

`car_app` 是机器人巡逻任务的 Python 上位机。正式入口 `python3 -u main.py start` 由 `competition_runtime.py` 统一协调，复用阶段一地图遍历与运动、阶段二色块障碍识别、阶段三涵洞及人物／刀具识别。各阶段脚本保留独立入口；同一内容有冲突时，以当前阶段代码及下列正式融合规则为准。实车步骤见 [VEHICLE_ACCEPTANCE.md](VEHICLE_ACCEPTANCE.md)；`AUDIT_REQUIREMENTS.md` 中旧比赛时限、双端补查及返航预算条款属于旧实现记录。

## 2026-10-16：组合返程与独立读卡播报

组合启动仍为 `python3 -u main_stage12_combined.py`。普通道路避障掉头后复用正常路口检测：一组合格的停后新双墙即可启用检测，明确新开口优先，保留连续缺测结合原里程区间的辅助推断。取消返程额外的两组双墙及位移资格；越过预计入口只告警并继续等待激光，不凭里程单独停车或确认节点。入口确认并严格停稳后才执行新路线，起点HOME和已有短节点撤回流程保留。

巡逻卡只接受0扇区1块第0字节 `10、20、…、90、A0、B0、C0`，分别对应1～12号（A/B/C为10/11/12号）；不再接受数值 `01～0C` 或ASCII。UID只用于区分卡片和连续在场去重。读块保留150 ms窗口与300 ms轮询，完整成功响应提前交付；发送前残留独立记录，不作为新交易证据。恢复后首个真实合法交易才证明通信恢复，详细故障分类、恢复过程及每5秒统计写入日志。

搬运或推动小车检查读卡播报，在RDK的应用目录运行：

```bash
python3 -u test_rfid_patrol_audio.py
```

程序只连接读卡器和播放器，不要求姿态、激光、摄像头，不打开底盘或发送运动指令，也不写卡。终端显示UID、原始编号、巡逻号及播放结果，详细证据保存在本次日志目录。同卡持续在场只播一次，连续三次合法无卡后再次读到才重播；传输错误不算离开。默认持续运行，`q`回车／Ctrl-C／EOF结束，排队音频最多收尾30秒。该程序与组合入口复用同一读卡及逐请求播报链路，不生成实际道路定位；真实声音须现场听验。本轮仅做外置针对性桌面回归，不代表完整项目回归或整车验收通过。

## 静止人脸与刀具识别测试

小车保持停车，使用独立peopleknife BPU模型和20类音频持续识别，不进行行驶或左右扫描，也不要求双墙、RFID或CH5触发。RDK上运行：

```bash
cd /root/car_app
python3 -u test_face_knife_preview.py
```

无需浏览器；终端显示启动提示、首次健康新鲜推理完成后的“识别已就绪”、故障、保存成功的完整绝对路径及结束结果。无目标的成功推理也属于已就绪。输入 `q` 后回车或按 `Ctrl+C` 结束，没有总运行时限。可用 `--camera-index 1` 或 `--camera-device /dev/video2` 选择摄像头，用 `--output-dir /root/识别照片` 指定保存目录；不再提供HTTP/MJPEG服务及相关参数。

- 启动先确认BRAKE接受与应用，验证双轮连续500 ms里程不变，再固定舵机CH1上下800 μs、CH2左右1500 μs，确认应用并等待到位后识别。运行持续监督停车状态；正常退出再次确认停车并保持该PWM。确认遥测不能代替机械角度实测。
- 人物类别1～10对应人脸1～10号，刀具类别11～20对应刀具1～10号。置信度≥0.80，连续两张不同新鲜画面的最高分类别编号相同才触发保存和播报；同分按类别编号升序选择。照片绘制该帧全部达标目标框，使用真正送入YOLO的原图。最高分编号已完成且仍可见时不重复触发，也不转播较低分目标；只有可靠画面连续5秒未出现该编号才允许再次触发。
- 保存与语音分别确认完成。音频缺失或播放失败仍保存照片；保存失败不记为已保存。重试只补做失败的一项，避免重复照片或重复播报；音频结束后由随后两张新图重新确认，不积压候选。
- 对应带框JPG及编号、分数、采集时间JSON异步保存至 `资料/静止识别测试/<本次运行目录>/`，每次运行使用独立目录、唯一文件名。保存使用有界队列，实际两份文件写入成功后才打印照片完整绝对路径；失败提示并记日志，识别继续。
- 健康新鲜推理无达标目标时，首次及持续未命中满5秒、10秒各保存一张实际推理原图和JSON到本次目录的 `diagnostics/`；整次运行最多3张，恢复不重置额度。诊断图不计识别成功、不播报。日志和诊断JSON记录同帧阈值前最高分、业务编号、分类输出范围及达标候选数，识别门槛仍为0.80；运行阶段按实际加载、识别、恢复和退出状态更新。
- 摄像头或推理异常时保持停车，暂停新增触发，每隔1秒自动重试。恢复废止旧代次结果和未确认计数，保留已完成的保存及播报记录；故障和缺帧不计入5秒消失时间。摄像头保持单采集owner，挂起推理在旧独立进程终止后重建；通信故障或底盘异常停车退出。

本测试的 `peopleknife.pt` 经ONNX、校准量化转换为 `assets/peopleknife_yolo/peopleknife_bayese_640x640_nv12.bin`，同目录 `runtime-manifest.json` 保留原20类通道到业务编号的映射及模型SHA-256；转换、校准和运行统一采用640×640 letterbox/NV12。该模型仅用于本静止测试，不替换障碍物模型或正式阶段3默认模型。转换中间文件及对照报告保存在外置 `car_app_tests/`；量化可能降低分数，转换对照不代表独立实景检测精度。

电脑只通过外置 `car_app_tests/` 中的设备替身测试，不直接运行本实车入口。实际摄像头、BPU吞吐、扬声器及机械姿态需要分别在RDK／现场验收；本轮实现不自动上传、烧录或启动设备。

## 2026-10-14：v17适配、10／40 mm出发与读卡播报（当前规则）

本节覆盖十二个比赛入口、main start、两套阶段1及阶段2。普通入口采用`10mm_turn`，原地转入口已直接改名为`_40mm_pivot.py`，旧`_20mm_pivot.py`启动命令不再支持。距离仍从首次保存正常转弯决定时的STATE双轮轮程计起，10／40 mm是BRAKE触发阈值，不是最终地面停点。

底盘通信保持一个所有者，正常100 ms续约、200 ms确认、500 ms逐轮严格停稳及原额外等待不变。确认期限从真正serial.write开始，完整写入成功后才提交命令记录；慢门禁不能提前消耗确认窗口。UART接收和安全检查先于外设事件，外设每轮最多16件或2 ms；视觉／相机控制锁最多等待5 ms，锁忙重算当前提案，不后台重放旧目标。障碍先发布停车事实，再由控制线程按原帧时刻和道路上下文冻结位置。

按实际v17源码区分可恢复通信诊断`0x00000F3F`和运动安全故障：诊断只记录，不单独停车；真实确认超时、租约、DMA、陀螺仪、编码器及未知安全故障继续保护。转角未达标按现有绝对终点自动恢复／补角方案处理，±5°完成容差、原转速和HELLO静止门禁保持；陀螺仪无效时不放行盲直行。

RFID收到合法巡逻卡就排队播报，每次经过一次；持续在场不重复，三次合法无卡后再次进入才重播。读卡失败不停车、不要求集齐12卡、不输出RFID成功／失败清单，原始异常保留日志。读取保持150 ms预算，按长度分帧且保留分片，只有连续三次需要重建传输的交易失败才后台恢复，重试至少间隔1秒；非法卡内容不反复重开串口。阶段2不创建RFID组件。

本轮源码、桌面回归和现场边界见[本轮验证报告](../car_app_tests/artifacts/v17-host-repair-20261014/verification.md)。未执行RDK上传、STM32烧录或整车验收。

普通比赛行驶相机掉帧、超时和推理故障不触发BRAKE，也不拦截最终UART，保留下层导航及已有合法限速，不新增障碍接近减速。首次启动仍需当前代次两张新鲜成功帧。正常转弯前不等画面；保存决定至补角停稳暂停形成新障碍，废止未确认候选及旧异步结果，已锁存任务仍保留。直行穿口继续原两帧障碍确认并按源时刻位置封前向道路。补角停稳后仅用当前代次、转后及前向姿态屏障之后的真新图，无命中／无候选才离口，无图保持停车；转后目标封尚未离口的新前向道路并在原节点精确重规划。出发后只后台软件重开相机，不做阻塞运动的USB复位；启动停车保留USB恢复。通信、陀螺仪、逐轮编码器及其他真实故障保护保持。

## 自检与比赛

调试时执行独立完整自检；未提供子命令也默认执行它：

```sh
python3 -u main.py selfcheck
```

完整自检保留独立 300 秒检查预算和共享 v9 配置，不启动导航。它先确认零速／STOP，再检查地图、映射、云台六步往返、相机、模型、WAV／静音输出和 RFID，最后检查遥测。完整云台顺序是左打死 → 右打死 → 左右居中 → 下打死 → 上打死 → 共享水平配置 800 μs。它与正式比赛的自动启动是两个入口。

正式比赛只需：

```sh
cd /root/car_app
python3 -u main.py start
```

`start` 不要求人工输入 PWM、`mark` 或巡航速度。它完成MCU握手与时钟依据、零速／严格停稳和停车采样，检查线索／WAV／音频，自动确认左右1500／上下600，加载人物刀具模型，启动相机及后台RFID，再在独立进程中计算并校验完整路线。运动和相机启动证据齐备才平移，不等待上层数值或RFID恢复；旧入口默认第一套。`q`回车／Ctrl-C可请求退出。

相机暂缺时，正式启动停车，唯一相机服务后台恢复；首次放行需当前代次两张不同新鲜成功帧。出发后视觉故障不刹车，后台只软件重开；缺帧不等于确认无障碍。正常转弯及补角停稳后仍需前向新图，无图保持停车。涵洞两侧各最多5秒真实识别，结束后确认归中600及到位直接续行，不等相机。正式比赛没有浏览器预览。

| 条件 | 正式 `start` 行为 |
| --- | --- |
| MCU、停稳、航向、下层导航、命令确认 | 保留阶段一门禁；故障先停车，满足恢复与位置核验后继续 |

| RFID | 交易异常后台恢复，不单独阻止车辆任务，记录可能漏读时段 |

无全场 600 秒截止时间，也不使用单道路 elapsed 超时、返航时间预算或估计行驶时间制造节点。200 ms 命令确认、独立 5 秒严格停稳等局部保护仍有效；涵洞视觉故障在每侧5秒到期后静默结束，云台／音频动作失败仍停车恢复，不能把“没有全场时限”理解成取消局部故障保护。异常恢复不重置道路原点、已完成道路、永久封路或涵洞固定墙侧结果。

此入口独立校验协议 2.3、固件标识 `car12-single-wheel-v12` 和能力 `0xEDB`，不使用共享 v9 固件标识。若旧脚本报“需要 car12-wheeltrace-v9”，将更新后的 `test_camera_pwm.py` 同步到 RDK 后重试，无需改全局 `config.py`。

先退出比赛或其他占用 STM32 串口的程序，在 RDK Bash 运行：

```sh
cd /root/car_app
python3 -u test_camera_pwm.py
```

每行输入两个 500～2500 范围的整数，顺序是**左右 PWM、上下 PWM**，单位 μs：

```text
1500 700
1600 700
1500 800
1500 700
q
```

每次回车都会实际发送一次设置，包括重复输入相同数值；依次确认匹配 ACK、应用序号和 PWM 开启，再显示结果。CH1/PB6 对应上下，CH2/PB7 对应左右。软件确认不能证明引脚波形或机械角度，请观察实际舵机动作。可用 `--port /dev/ttyUSB1` 或已确认的稳定设备路径指定 STM32。

工具只初始化 MCU 与云台，不启动摄像头、RFID 或导航；启动先确认零目标及 STOP，不自动改变云台姿态。等待输入时持续接收遥测，命令失败、会话变化或已开启 PWM 被关闭时终止。输入 `q`、EOF 或 Ctrl-C 时尝试确认 STOP 并关闭串口；下位机按 STOP 协议关闭舵机 PWM，不自动回中。运行日志与原始收发保存在本次日志目录。

### 摄像头上下水平标定

在 RDK 的应用目录运行：

```sh
python3 -u main.py gimbal-test
```

默认使用 `config.py` 的 MCU 串口；已确认设备路径后，可用 `python3 -u main.py gimbal-test --port /dev/ttyUSB1` 指定串口。工具只初始化 MCU 与云台，先确认零速应用回读和 STOP，再开始调整，不发动车轮。左右固定为 1500 μs 中位，上下先回到当前配置的水平值 800 μs。你直接观察摄像头实物；工具不打开相机、不提供预览。

| 输入 | 作用 |
| --- | --- |
| `set 800` | 将上下 PWM 设为指定整数，单位 μs；800 为当前实测水平值 |
| `+25` / `-25` | 从上一次已确认的上下 PWM 增加 / 减少指定脉宽；实际抬头或低头方向由你观察 |
| `down` / `up` | 分别测试 500 / 2500 μs 的上下极限 |
| `center` | 恢复本轮已标记的水平值；尚未标记时恢复当前配置值 |
| `mark` | 你确认摄像头已水平后，记录当前已确认 PWM，并输出可复制的反馈摘要 |
| `help` / `q` | 查看帮助 / 退出 |

先用 25 μs 步长粗调，再用 5 μs 步长微调。只接受 500–2500 μs 范围内的整数；无效或越界输入不发送命令。每次调整等待 MCU 命令接受、应用序号回读确认和 0.6 秒到位时间，再显示本次已确认应用的 PWM；协议不回读实际 PWM 数值或机械角度，这些确认不能代替你对实物角度的判断。等待键盘输入期间，主线程每 20 ms 继续处理输入队列与 MCU 遥测，输入线程只负责读取命令。

复核已确认的水平值可按以下顺序操作；若更换舵机或安装位置后尚未水平，继续调整，只有你观察到真正水平时才输入 `mark`：

```text
set 800
mark
q
```

`mark` 只保存本轮水平值并打印 / 记录反馈，不修改 `config.py`。退出时尝试恢复本轮已标记的水平值；未标记则恢复原配置值。正常退出、输入结束（EOF）、异常和 Ctrl-C 都执行停车与关闭，通信确认和姿态恢复均有超时；恢复失败保留错误并报告失败。

当前实测水平值 800 μs 保留在共享配置，供完整自检和独立标定工具使用；正式融合比赛单独使用上下 750 μs／左右 1500 μs。各阶段入口仍按其当前代码及下方说明运行。后续重新标定时，请复制工具输出的 `SERVO_TILT_CENTER_US = 数值`，并补充 `down` 实际是否低头、`up` 实际是否抬头；将确认的新水平值回填共享配置后，按 [实车验收清单](VEHICLE_ACCEPTANCE.md) 重测。

仅收集 MCU 通信证据时可运行：

```sh
python3 -u main.py selfcheck --passive
python3 -u main.py diagnose --duration 20
```

被动模式只建立 MCU 连接、发送 HELLO 并读取遥测，不发送运动、云台、补光命令。`diagnose` 的时长必须大于 0 且不超过 120 秒。其退出码 `0` 只说明握手成功，不能替代完整自检或实车验收。

被动自检不执行零速校时；若首次握手较慢，现有协议不能仅凭被动接收确定样本时效，可能保守报陈旧。需结合 `diagnose` 的原始时序及主动自检应用回读排查，不能单凭该结果认定传感器损坏。

## 正式比赛的上层、道路与任务归属

仅右上CH5的有效数值参与涵洞触发：同会话／boot、真实源龄≤250 ms、源键推进且距离有限并小于65535。无有效数值表示当前无目标，不阻止启动或导航；上层状态码不锁存运动故障，CH4不参与。本道路首个真新鲜数值即可触发，无需开阔边沿；重复、旧源或空值不能触发。

正式任务始于 `n01`、车头朝 `n03`，地图包含 20 个节点、29 条道路。唯一协调器保存道路 ID、原入口／目标节点、道路内有符号编码器进度、道路参考航向、行驶方向及会话／boot；每次经过有独立道路上下文。障碍图像、上层样本和 RFID 读卡按各自真实源时刻归属到该上下文，迟到结果不能写入下一条道路。转弯／掉头后更新方向，暂停和恢复不能把当前位置重设为零。

道路边界按阶段一真新鲜开口与路线顺序推进，结合编码器和转弯方向判断所处道路。名义长度与编码器不符时告警并记录，不另加数字限距停车门槛，不凭估计时间跳节点。道路上下文无法可信确认、boot 改变或人工搬动车辆时，保持停车等待位置核验。

固定隧道为 `r07`、`r14`、`r21`、`r28`，与可移动涵洞分开处理。它们两侧是无识别目标的白墙，不能按“两侧物理无墙”解释。任意时刻、任意方向经过这四条道路均不做障碍视觉检测、涵洞停车、左右扫描、人物／刀具识别；相机可继续后台采集恢复，下层导航、编码器、航向、通信与真实故障保护照常工作。每条普通道路最多一个涵洞，每场最多预期三个不同障碍道路。

## 精确路线与障碍封路

初始和每次封路后都覆盖当前起点可达、尚未完成且未封闭的全部道路。已完成道路可重复作为捷径，未经过道路也可使用；节点可左右转或掉头，遇障碍可在路中原地掉头。目标先最小化地图整数毫米总路程，再在所有等长方案中最少化转弯动作：直行 0、左右 90° 和 180° 各 1，计入给定起始航向的首动作，最终到达不额外计转弯。

`competition_planner.py` 在独立 `spawn` 进程中完成精确求解，没有固定规划时限、贪心结果或近似 fallback。主进程保持严格静止、处理遥测与退出输入；完整结果到达后独立校验道路连续性、封路、覆盖、终点、距离、转弯和撤回前缀，验证通过才允许平移。校验本身不重复求解；最优性来自可信规划进程的精确搜索，`optimal=True` 标记本身不证明任意外部路线最优。HOME 可达就回 `n01`；HOME 不可达则仍完成所有可达剩余道路，在所有可达终点中选总路程最短、等长少转弯的终点，明确报告未返航和不可达道路。

确认障碍后的顺序固定为：**BRAKE → 严格停稳 → 永久封闭无向整条道路 → 如同时有同路涵洞任务先完成扫描 → 原地左掉头 180° → 严格停稳 → 算完并校验“撤回原入口＋覆盖剩余可达道路＋可达时回 HOME”的完整路线 → 才开始撤回平移**。转过头不能直接放行旧路线。唯一封路例外是本次障碍点沿已进入的半段撤回原入口；不穿越障碍、不从对端补查、不恢复封闭路，也不把撤回算成整条道路走通。

在后续未封闭道路遇到新障碍按同一规则重规划；封路集合持续累积，重复事件不增加道路数量。如果意外出现第四条封路，记录超出赛场预期的告警，仍封路并精确重规划，不因此忽略障碍。返回原入口按阶段一开口／末段编码器和停稳证据确认，不能仅凭“走够时间”或“已掉头”认为到达。掉头后的撤回初始化和入口路线安装按阶段保存，故障恢复继续未完成操作，不重复已完成掉头／规划或推进路线索引。获准撤回片段如果再次确认前向障碍，则停车等待人工核验位置和通路；此时继续掉头会朝向原障碍，已有撤回授权不能放行该动作。

## 色块识别、涵洞和优先级

障碍识别以阶段二当前代码为准。使用**全帧面积**作为分母：蓝红牌12%、橙色牌10%、木栅栏19%，连续两张不同、新鲜、同目标画面达标才进入接近，前进基准为min(原基准,91) mm/s，保留居中和合法差速。已取得接近资格的同一目标连续两帧真实颜色触及完整画面最后一行即优先BRAKE；同两帧同时完成面积与触底确认时直接BRAKE，不等待91应用或实际达速。文字、栅栏空隙和边界框面积不计色面积；面积下降保持限速，两张有效新帧明确目标消失才解除。减速和制动尾段仍计入真实道路编码器进度。详细帧源、颜色占比及速度证据写入日志；正式main关闭预览。

路口转弯和涵洞任务优先于居中矫正，居中未达标不能拖延已保存的转弯；需转弯路口与涵洞同时出现时先执行地图转弯，本次扫描事件取消但不消耗该道路资格，以后仍可触发。同路障碍和涵洞同时出现时先停车封路、再扫描、再掉头及规划。已确认障碍、真实故障和严格停稳门禁始终抢占普通运动。

涵洞停车后上下800 μs左右扫描，车身左侧PWM2500／右侧500，归中左右1500／上下600。确认姿态并等待0.6秒后丢弃旧姿态／旧代次帧。默认及最低置信度0.8，同编号连续两个不同新鲜帧均达标即确认并结束该侧识别。各侧从到位屏障起最多5秒真实识别，掉帧、推理及视觉重试计时，换代／重建不续期。到期无可靠结果记该侧完成但识别失败且静默，继续另一侧；成功音频及云台仍检查真实完成。

账本以**无向道路 ID＋固定墙侧**保存左右结果：按端点规范方向定义墙侧，反向行驶时交换车身左右，已完成同一墙侧不再重扫。识别到目标后，以 `culvert:<道路>:<固定墙侧>:<类别>` 请求音频；只有该请求真实播放完成才结束该侧。入队、其他同类别播报或失败进程退出都不能代替完成；失败停车重试原请求，已成功请求不重播。

两侧成功或超时失败都算任务结束，整条道路随后消耗涵洞资格，本场往返不重扫；日志分别记识别成功／失败。中断保留已完成墙侧及未完成侧的原截止时间。归中左右1500／上下600并确认姿态到位后直接恢复原路线，不再等相机；正常转后前向确认仍保留。

正式 RFID 复用阶段一读块规则：0 扇区 1 块第 0 字节只接受 `10、20、…、A0、B0、C0`，对应1～12号；UID 只作卡身份。后台读取完整 16 字节块数据，驻留去重、重新经过逐次记读卡与播报请求；原始响应、错误和请求结果进入账本。缺失号码或失败播报单列报告，不为漏读额外加回访路线。地图巡逻号不代替实际读卡。RFID／音频失败停车等恢复；每个巡逻通过事件有独立音频请求，重试不重播已成功请求。

以下“四路组合更新周期”是共享诊断／旧导航的显示说明，不是正式融合 start 的运动门禁。共享显示按该周期打印：从上次输出后，下侧 `directional_cycle_seq` 和上侧 `upper_cycle_seq` 各至少更新一次，收集后按 CH1 → CH2 → CH4 → CH5 输出整块，以分隔线结束。两组周期号无需相等；数值不变也算新周期，上方新鲜的无目标 / 超量程和原始 `65535` 均可正常成组。固件没有统一的四路物理轮次标记，因此这只是最新两组数据的组合，串口批量接收或内部等待可能合并中间周期。导航计算仍按原有周期进行，不等待打印凑齐。本轮阶段一直接使用运动参照的显示和原始记录，不等待上层更新；下层方向按 CH2 左下、CH1 右下显示，并补充当前道路、下一动作、巡逻号和返家误差。

## 返航与结束

正式比赛无全场截止时间，也不依据 `RETURN_BUDGET_CALIBRATED`、单道路 elapsed 预算或扫描返航时间余量决定行动。HOME 可达时，返家是完整覆盖路线的一部分，可经过重复和未经过的未封闭道路；HOME 被封路隔断时按精确自由终点方案完成可达道路后停车。封闭道路只允许本次撤回前缀。

正常 `r01` 返家保留阶段一约 61 mm/s、160 mm 编码器末段与停稳核验；路中障碍撤回 `n01` 按本次已走有符号进度、制动余量及停稳证据处理。最终朝向、末端净距和制动尾段仍需实车验收。路线结束后保持停车，逐请求完成音频收尾，失败持续重试；可随时 `q`／Ctrl-C 中断。

| `start` 退出码 | 含义 |
| --- | --- |
| `0` | 本次路线结束并覆盖所有可达未封闭剩余道路 |
| `1` | 路线结束但可达道路覆盖未完成 |
| `2` | 组件构造、非法地图或未处理执行异常导致未完成 |
| `130` | q、EOF 或 Ctrl-C 中断并尝试停车清理 |

退出码 0 不等于全部赛场任务实物合格：末尾 `competition_summary` 分别报告完成／封闭／不可达／未覆盖道路、实际停车节点、是否回到 n01、涵洞两侧及未完成道路、RFID 漏号、音频逐请求结果和退出原因。`culvert_untriggered_roads` 列出已走普通道路中未触发扫描的道路，不证明没有涵洞；`visual_gap_roads` 单列存在视觉观测空缺的普通道路。未返航、漏读、未触发涵洞及真实播报质量均需查看证据，不补写成功。每场重新建立路线、位置、封路、RFID、涵洞固定墙侧和音频请求状态，保留历史日志和部署资产。

## 日志与问题复现

MCU 链路打开时自动建立原始采集；有运行日志会话时复用同一个运行目录，否则独立建立目录，无需另一个采集命令：

```text
logs/<YYYYMMDD-HHMMSS-随机运行号>/
    run.log
    events.jsonl
    rx.bin
    tx.bin
    wire.jsonl
    wheel_trace.csv
    manifest.json
```

`run.log` 是可读日志；`events.jsonl` 每行一个 JSON 事件，包含运行号、序号、UTC 时间、单调经过时间、事件名、消息和业务字段。控制台输出、异常详情、动作、障碍、涵洞、播报及最终账本会写入日志。完整 / 被动自检另外写 `logs/selfcheck_<时间>.log`；诊断另外写 `logs/rdk_diagnose_<运行号>.txt` 和 `.json`。

`rx.bin` / `tx.bin` 保留链路实际收发的原始字节；`wire.jsonl` 保存相应串口事件和时序，`wheel_trace.csv` 保存有效追踪帧的原始字段及主机接收时间、帧序号。`manifest.json` 保存固件标识、会话和代码校验信息，分别报告主机采集完整性、追踪采样完整性和命令发送完整性；只有三项均通过时整体 `complete` 为真。队列满、写盘异常、追踪样本缺口、帧解码失败、部分写入或关闭超时会留下不完整证据，不能把文件存在视为完整采集。同一运行目录再次打开链路时，在 `mcu-<capture_id>/` 中保存新采集，避免覆盖前一会话。固定运动、交互运动和极性脚本沿用自己的终端输出节流，并通过运行日志会话显示采集目录、异常与完整性摘要。

主动运行结束、Ctrl-C 或故障时先尝试 STOP，再接收约 1.1 秒尾段并有界关闭文件和设备；正式比赛没有全场时限，尾段只用于停车后证据收集。被动诊断、自检被动模式和端口识别继续只发送 HELLO，不为采集尾段额外发送 STOP。录下的软件驱动输出及停车尾段不能证明硬件已停止、机械制动距离或实际电机端电压。

主程序和阶段测试的状态日志约每秒输出一次最近已知业务快照；固定运动、交互运动、极性和串口识别入口关闭这项周期输出，沿用各自的反馈节奏。`source_age_s` 是该快照距离最近一次业务更新的年龄，**不是新收到的硬件遥测**；长时间初始化或设备等待期间尤其要区分。检查 `phase`、当前组件／道路、规划／停车状态和相关失败事件来判断停在哪里；旧诊断的 deadline 字段不代表正式比赛存在全场时限。

正式融合关键日志包括 `competition_road_context`、`competition_road_blocked`、`competition_plan_validated`、`competition_culvert_entry`、`competition_culvert_complete`、`competition_peripheral_wait`、`competition_service_failed` 和 `competition_summary`；结合源时间、道路上下文、会话／boot、原始 rx／tx 与逐请求音频状态判断。上层超量程和超龄分别查看，等待／恢复记录不等于涵洞扫描完成。共享诊断旧 `upper_scan_degraded`／`upper_scan_recovered` 仅按该入口解释。

终端和文件使用独立非阻塞队列。队列满或写入失败时控制流程不等待日志，`log_terminal_dropped`、`log_file_dropped`、`log_terminal_error`、`log_file_error` 记录丢弃数量或写入错误。退出只做有界等待，极慢写入、磁盘异常和进程突然结束可能留下不完整日志，不能宣称日志零丢失。

每场正式比赛的路线、永久封路、活动道路进度、涵洞固定墙侧与音频请求账本从空开始；不存在补查栈或全场截止时间。三场连续运行见验收清单。
